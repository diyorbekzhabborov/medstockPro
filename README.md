# MedStock Pro — Система учёта медицинского склада и списаний

> **Десктоп-клиент (Windows offline/online), облачный бэкенд и мобильный PWA-кабинет руководителя**  
> Полная реализация в точном соответствии с **Техническим заданием (ТЗ) Версии 1.0**.

---

## 🏗 Архитектура экосистемы

Система построена по **гибридной Offline-First топологии**:

```
                               ┌────────────────────────────────────────┐
                               │   Облачный бэкенд (Node.js API)        │
                               │   Порт :4000                           │
                               │   - Централизованная БД                │
                               │   - Шлюз двусторонней синхронизации    │
                               │   - Авторизация JWT & Аналитика        │
                               └──────────────────┬─────────────────────┘
                                                  │
                 ┌────────────────────────────────┴────────────────────────────────┐
                 │                                                                 │
                 ▼ (Синхронизация по кнопке)                                       ▼ (REST API)
┌─────────────────────────────────────────┐                     ┌─────────────────────────────────────────┐
│ Рабочее место склада (Windows PC)       │                     │ Кабинет владельца (iOS / Safari PWA)    │
│ Порт :3000                              │                     │ Порт :5000                              │
│ - 100% Offline-First на SQLite БД       │                     │ - Стиль необанка (Revolut / Alif Mobi)  │
│ - Мгновенный приём и продажа            │                     │ - Финтех-виджеты капитализации          │
│ - Списание в клинику (0.00 TJS)         │                     │ - Счётчик долгов «Мне должны клиенты»   │
│ - Интеграция с банками Таджикистана     │                     │ - Погашение долгов в 1 клик             │
│ - Сканирование штрихкодов & печать чека │                     │ - Напоминания в WhatsApp / Telegram     │
└─────────────────────────────────────────┘                     └─────────────────────────────────────────┘
```

## 🚀 Быстрый запуск (1 клик на Windows)

В корневой папке проекта подготовлены удобные скрипты запуска:

| Файл | Описание |
| :--- | :--- |
| **`start-all.bat`** | **Запустить всю экосистему разом** (Бэкенд :4000, Терминал :3000, PWA :5000) и открыть в браузере |
| **`start-desktop.bat`** | Запустить только **Рабочее место склада (Windows)** |
| **`start-pwa.bat`** | Запустить только **Кабинет владельца (PWA)** |
| **`start-backend.bat`** | Запустить только **Облачный API-сервер** |

## 💼 Соответствие разделам Технического задания

### 1. Карточка товара и автоматический финансовый баланс остатка (Раздел 2 ТЗ)
- **Поля:** Наименование, Артикул/SKU, Штрихкод (1D/2D), Фотография, Остаток на балансе, Розничная цена (TJS).
- **Вычисляемое поле:** `Количество × Розничная цена за единицу` (Стоимость складской партии).
- **Пример из ТЗ:** При оприходовании 10 000 шприцев по 1 TJS система фиксирует плановый баланс склада: **10 000 TJS** крупным финтех-виджетом.

### 2. Сценарии списания со склада (Раздел 3 ТЗ)
- **Сценарий А: Продажа клиенту**
  - Списание физического остатка (`Новый остаток = Предыдущий - Количество`).
  - Фиксация выручки или дебиторской задолженности.
- **Сценарий Б: Списание в частную клинику**
  - Внутреннее хозяйственное потребление частной клиникой.
  - Физический остаток уменьшается, сумма оплаты строго **0,00 TJS** (не формирует долг и выручку).
  - Статус операции: `«Использование в клинике (Внутр. расход)»`.
  - Отдельный учет в ежемесячном показателе руководителя: `«Расход клиники»`.

### 3. Способы оплаты и банки Таджикистана (Раздел 4 ТЗ)
- **Наличный расчёт:** Касса склада (сомони наличными).
- **Безналичный перевод:** Банки РТ:
  - 🟣 **Dushanbe City (DC)**
  - 🔵 **Банк Эсхата**
  - 🟢 **Алиф Банк / Alif Mobi**
  - 🟢 **Амонатбонк / Другой банк**
  - Ввод номера квитанции / транзакции.
- **В долг (Под реализацию):**
  - ФИО контрагента, телефон (+992), срок возврата.
  - Сумма автоматически зачисляется в реестр `«Дебиторская задолженность» (Кто мне должен)`.

### 4. Offline-First архитектура и синхронизация (Раздел 5 ТЗ)
- Локальная база данных SQLite прямо на Windows PC (`desktop/local_warehouse.db`).
- Оператор может работать при полном отсутствии интернета.
- **Кнопка «Синхронизировать»:**
  - Отправляет накопленные локальные чеки (`sync_pending = 1`) на облачный сервер.
  - Принимает обновления номенклатуры и статусы долгов.
  - Наглядные статусы: `Онлайн`, `Офлайн (локальная SQLite)`, `Синхронизировано`.

### 5. Мобильный PWA-кабинет руководителя (Раздел 6 и 7 ТЗ)
- **Стиль необанка** (Revolut / Alif / Kaspi) с медицинской эстетикой (акценты `#0284C7`, `#0D9488`).
- **Главный экран (Dashboard):**
  - **Капитализация склада** (TJS).
  - **Счётчик долгов** («Мне должны клиенты»).
  - **Расход клиники** (Стоимость медикаментов за месяц).
  - **Выручка за сегодня** (Наличные vs Безнал по банкам DC / Эсхата / Alif).
- **Раздел «Дебиторы (Долги)»:**
  - Список должников, телефоны, даты, статусы просрочки.
  - Кнопка **«Погасить долг»** (с выбором банка или кассы).
  - Быстрый звонок `tel:+992...`
  - Отправка напоминания в **WhatsApp** и **Telegram** с готовым текстом на русском и таджикском языках.
- **Лента активности:** Полное соответствие журналу из страницы 3 ТЗ:
  - `Списание #1042` | Шприцы 5мл (100 шт.) | Продажа (Dushanbe City) | +100 TJS (Оплачено)
  - `Списание #1043` | Капельницы инфуз. (25 шт.) | Использование в клинике | 0.00 TJS (Внутр. расход)
  - `Списание #1044` | Физраствор 200мл (50 шт.) | В долг (Аптека «Шифо») | +350 TJS (Дебиторка)
- **PWA-поддержка:** `manifest.json`, Service Worker, Apple Touch Icon, полноэкранный режим без адресной строки Safari (Add to Home Screen).

## 🧪 Автоматическое тестирование

Для запуска полного цикла интеграционных тестов:

```powershell
# Запустите бэкенд, десктоп и pwa, затем выполните:
node tests/verify-all.js
```

Тест проверяет все 8 ключевых сценариев:
1. Доступность API и шлюза синхронизации.
2. Локальную автономную SQLite БД терминала.
3. Оформление продажи (Сценарий А) с безналом Dushanbe City.
4. Списание в клинику (Сценарий Б) строго по сумме 0,00 TJS.
5. Фиксацию дебиторской задолженности (В долг под реализацию).
6. Двустороннюю синхронизацию по кнопке.
7. Расчёт дашборда владельца в PWA (Капитализация, Долги, Выручка, Клиника).
8. Формирование текстов напоминаний для мессенджеров на двух языках.
